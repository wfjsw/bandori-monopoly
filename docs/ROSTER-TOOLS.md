# Roster tools (post-JSON)

`data/{cards,characters,bands}.json` are **gone**. Card / character / band
metadata is defined in the Rust rule code and exported from the ruleset
(ABI v63 `ruleset_metadata`). Tools that need JSON rows read a dump of that
export instead.

## Produce the dump

```sh
node tools/roster-dump.mjs              # -> target/roster-dump/ (cached)
node tools/roster-dump.mjs --force      # re-dump after a Rust roster change
node tools/roster-dump.mjs --out DIR    # custom directory
```

This wraps:

```sh
cargo run -p rules-native --example dump_roster -- <dir>
```

which writes `cards.json` / `characters.json` / `bands.json` in the exact JSON
shape / key order / formatting of the retired `data/*.json` files (including
the flat arrays under the `"cards"` / `"characters"` / `"bands"` keys).

Do **not** set `CARGO_TARGET_DIR` for this (or `tools/build-ruleset.mjs`) -- an
externally set one stages stale artifacts.

Display-only columns that live outside the engine structs (`counterReason`,
and the slimmed roster copy -- card `text` / `rawName` /
`cell`, persona `display` / `text` / `color` / `variantTag` / `art` /
`costume` / `cnId`, group `shortName` / `color` / `text` / `logo`) are **not**
in the dump. `display.json` is the source for the rest of the display copy.

## Consume the dump (Python)

`tools/roster.py` is the single loader:

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parents[1]))  # tools/
from roster import load_cards, load_characters, load_bands
```

It resolves the dump directory as:

1. `$ROSTER_DIR` if set
2. `<repo>/target/roster-dump/` otherwise

and exits with a clear error naming `node tools/roster-dump.mjs` when the files
are absent. Stdlib only; works under `python3 -I`.

## Who reads it

| Tool | What it takes from the roster |
| --- | --- |
| `tools/asset-pipe/check.py` | card / character / band inventory vs manifest art |
| `tools/rulebook/extract.py` | card ids + names to match rulebook sheet cells |

`tools/rulebook/{check,cite}.py` read `docs/rulebook/cards.json` (the rulebook
sheet extract -- a **different** file) and do not need a dump.

`rules/kani/build.rs` and `tools/kani/gen_card_ids.py` scan `rules/**/*.rs`
sources for ids; they do not read the dump.

## What changed at the JSON cutover

* **`tools/roster-dump.mjs` + `tools/roster.py`** -- new; the one way tools get
  roster rows.
* **`tools/asset-pipe/check.py`** -- roster coverage now comes from the dump
  (`load_cards` / `load_characters` / `load_bands`) instead of `data/*.json`.
* **`tools/rulebook/extract.py`** -- matches sheet cells against dump card ids
  (`load_cards`); output is still `docs/rulebook/cards.json`.
* **`tools/asset-pipe/extract.py`** -- no longer copies or writes
  `cards.json` / `characters.json` / `bands.json`, and no longer merges
  `skill_simple` into those files. Every other extraction (images, audio,
  fonts, live2d, text, other `data/*.json`) is unchanged.
* **`tools/lift-roster.mjs`** -- **deleted**. It was the one-shot JSON → Rust
  lifter (184 cards / 54 characters / 12 bands, proven byte-equal by
  `cargo test -p rules-native --test roster_equiv`). The lift is complete;
  do not resurrect it. Generated-file headers in
  `rules/ruleset-core/src/roster_order.rs` and the two `roster_table.rs`
  files still say "generated by tools/lift-roster.mjs" as a historical note.

## Equivalence gate (unchanged)

```sh
cargo test -p rules-native --test roster_equiv
```

Deep equality (order included) for every row that has Rust metadata, with
coverage constants `EXPECTED_*_COVERAGE` at 184 / 54 / 12. Until the JSON
files are deleted by the integrator, this test still diffs against them;
after deletion that test's JSON side needs the same dump (out of scope here).
